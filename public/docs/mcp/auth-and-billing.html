Reference

Authentication & billing

human account + prepaid meter. Portal and MCP debit the same meter. No free anonymous MCP. API keys planned later — do not invent endpoints.

Account

  • Human registers; owns portal and MCP enablement
  • Signup requirements published with the account flow

Prepaid meter

  • Fund in advance; production debits the balance
  • Shared by portal and MCP
  • Insufficient balance blocks production (no silent overdraft)

MCP auth

Credentials issued with access for that account. Not published on this site.

Roadmap

PhaseAuthBilling
Now Human account; MCP tied to account Prepaid meter funded by human
Later (planned) API keys / programmatic credentials for agents API-oriented billing options (details TBD)

Until API keys ship, account + meter is the only model.

Security

  • Never put funding credentials in prompts or public repos
  • Prefer human approval for high-cost or Certified jobs
  • Recipient data is production mail data — handle under your policies
